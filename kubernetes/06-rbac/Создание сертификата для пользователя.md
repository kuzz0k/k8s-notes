Задача: ограничить пользователя `Arthur` только к ns `test`, для этого нужно:
1. Создать ключ
2. Создать сертификат и  подписать его в центре сертификации кластера
3. Сконфигурировать файл, чтобы пользователь мог ходить в кластер

В Kubernetes пользователей как таковых нет. Но можно эмулировать доступ пользователя используя ssl сертификаты. Для этого имя пользователя добавляют в dn сертификата. Например:

```
cn=matthew,dc=kuz,dc=local
```

Генерируем ключ

```
openssl genrsa -out matthew.key 4096
```

Создадим временную директорию

```
mkdir users
cd users/
```

Создадим конфигурационный файл opessl csr.cnf.

```
[ req ]
default_bits = 2048
prompt = no
default_md = sha256
distinguished_name = dn

[ dn ]
CN = matthew
DC = kuz
DC = local

[ v3_ext ]
authorityKeyIdentifier=keyid,issuer:always
basicConstraints=CA:FALSE
keyUsage=keyEncipherment,dataEncipherment
extendedKeyUsage=serverAuth,clientAuth
```

cn - common name

Генерируем запрос на сертификат.

```
openssl req -config csr.cnf -new -key matthew.key -nodes -out matthew.csr
```

Поместим содержимое файла csr в формате base64 в переменную среды окружения BASE64_CSR:

```
export BASE64_CSR=$(cat matthew.csr | base64 | tr -d '\n')
```

Создаём файл csr.yaml с запросом на подпись:

```
apiVersion: certificates.k8s.io/v1beta1
kind: CertificateSigningRequest
metadata:
  name: matthew_csr
spec:
  groups:
  - system:authenticated
  request: ${BASE64_CSR}
  usages:
  - digital signature
  - key encipherment
  - server auth
  - client auth
```

Применяем запрос:

```
cat csr.yaml | envsubst | kubectl apply -f -
```

Проверяем наличие запроса:

```
kubectl get csr
```

Подписываем и генерируем сертификат:

```
kubectl certificate approve matthew
```

Поместим сертификат пользователя в файл.

```
kubectl get csr matthew_csr -o jsonpath={.status.certificate} | base64 --decode > matthew.crt
```

Создание файла config  
Получаем информацию о подключении к кластеру.

```
kubectl cluster-info
```

Нас интересует строка

```
Kubernetes master is running at https://192.168.218.49:6443
```

Начинаем создавать файл конфигурации.  
Сначала добавим информацию о кластере.

```
kubectl config --kubeconfig=./config set-cluster k8s --server=https://192.168.218.49:6443 \
--certificate-authority=/etc/kubernetes/pki/ca.crt --embed-certs=true
```

Добавляем пользователя.

```
kubectl config --kubeconfig=./config set-credentials matthew --client-key=matthew.key --client-certificate=matthew.crt --embed-certs=true
```

Определяем контекст.

```
kubectl config --kubeconfig=./config set-context default --cluster=k8s --user=matthew --namespace kubetest
```

Устанавливаем контекст по умолчанию.

```
kubectl config --kubeconfig=./config use-context default
```

Проверяем доступ к серверу

```
kubectl --kubeconfig=./config -n kubetest get pods
```

Мы должны получить сообщение об ошибке доступа пользователя artur к ресурсу. Это нормально. На данном этапе мы сконфигурировали доступ к кластеру для пользователя – конфигурационный файл для программы kubectl.

Доступ к элементам API кластера мы будем описывать отдельно.

Скопируйте полученный config файл в домашнюю директорию пользователя matthew:

```
mkdir /home/matthew/.kube
cp config /home/matthew/.kube
chown -R matthew:matthew /home/matthew/.kube
```
