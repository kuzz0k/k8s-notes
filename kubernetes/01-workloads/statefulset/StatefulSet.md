Также как и Deployment оперирует подами, но предназначен для постоянной информации. Мы получаем гарантированный порядок старта, можно подключать volume к подам. 

`headless` сервис:
Предназначен для формирования dns имени конкретных подов, так как в отличие от Deployment нам необходимо обращаться к конкретному поду

Для того чтобы сделать headless сервис, достаточно указать `clusterIP: None` в сервисе:

```
spec:
	clusterIP: None
	selector:
```

после запуска манифеста в описании неймспейса можно заметить что у подов теперь появились 0, 1, 2

Посмотрим как работает обычный сервис. Запустим `curl` приложение-зеркало, которое возвращает запрос, который мы посылаем:

```
kubectl -n work run curl --rm -it --image=alpine/curl:8.14.1 -- /bin/sh
```

Параметр `--rm` удаляет под после выполнения команды, `-it` позволяет зайти в под и выполнять команды в интерактивном режиме, `--` - сам интерактивный режим

Попробуем достучаться до сервисов:

```
curl test-st

curl test-st-0.test-st-headless
```

# Порядок запуска, обновления, удаления

Поды запускаются в порядке возрастания индексов. Если в процессе запуска `test-st-2` упадет 1 или 0, то сначала 0 и 1 будут перезапускаться, а потом уже будет запускаться 2

Удаление происходит в обратном порядке, сначала `test-st-2`, потом `test-st-1` и тд. 

При выполнении `rollout restart` перезапуск идет в обратном порядке. Сначала последний, потом предидущий.

```
kubectl -n work rollout restart statefulset test-st
```

При желании порядок можно поменять через `.spec.podManagementPolicy` (по-умолчанию `OrderedReady`). `Parallel` - если порядок не важен, но рестарт будет по порядку
