Пользователь формирует правила и описывает их в манифесте и обращается с манифестом в k8s API, API сохраняет в базу данных (кластер вида ключ значение) etcd.

Controller с периодичностью опрашивает на появление новых данных и добавляет свои параметры.

Scheduler (планировщик) также смотрит в API и делает выводы на какую ноду положить приложение и добавляет эту информацию.

На каждой ноде кластера запущен kubelet, который контролирует состояние подов на ноде, если появился новый манифест, он добавляет через Containerd (может быть любая контейнирезации) контейнер из манифеста.

Также в ноде есть k-proxy, который отвечает за управление сервисами для распределения трафика, сети.
