Самый простой способ создания `persistent volume`. Позволяет монтировать директорию ноды в под. 

```
volumes:
- name: hostpath-volume
  hostPath:
    path: /tmp/hostpath-data
  type: DirectoryOrCreate
```

Type может быть [docs](https://kubernetes.io/docs/concepts/storage/volumes/#hostpath-volume-types). От него зависит реакция пода на директорию/файл на ноде

Запустим манифест, посмотрим логи, на какой ноде расположился под:

```
kubectl -n work logs hostpath-pod
```

```
kubectl -n work get pod hostpath-pod -o jsonpath='{.spec.nodeName}'
```

Далее провалимся на эту ноду и посмотрим директорию по пути, который указали в манифесте `/tmp/hostpath-data`

После удаления подов не забываем удалить директорию на самой ноде

### Обмен между подами на одной ноде

Таким образом можно организовать общение подов на одной ноде, но соотвественно нужно чтобы поды были на одной ноде, сделать это можно через `affinity`

### Риски и ограничения hostPath

Главная проблема - под может запуститься на другой ноде и будет потеря данных. Из-за этого необходимо прописывать `affinity`, давать лейблы или заражать ноды

### Проблемы безопасности

`hostPath` предоставляет контейнеру доступ к файловой системе узла. Это серьезная угроза безопасности и его использование должно быть строго ограничено

Пример: побег из контейнера через proc

Создадим под и зайдем в контейнер

```
kubectl -n work exec -it hostpath-pod -- /bin/sh
```

```
ls -l /data
```

Увидим все процессы и PID, в которые мы можем спокойно зайти и посмотреть содержимое

##### Безопасность

Чтобы предотвратить такой сценарий можно использовать `Kyverno` или `OPA Gatekeeper`, с их помощью можно поставить `clusterPolicy`, чтобы, например, hostpath можно было монтировать только из одной директории `/var/log/my-app`

##### Рекомендации

- Прописывать `NodeSelector` или `Affinity`
- Ставить `readOnly`
- Ограничивать доступ и никогда не монтировать `/` или другие важные директории

Для большинства задач лучше использовать более надежные и гибкие инструменты `Persistent Volume` в связке с сетевым хранилищем
