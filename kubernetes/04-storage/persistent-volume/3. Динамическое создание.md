### NFS provisioner

[nfs-provisioner](https://github.com/kubernetes-sigs/nfs-subdir-external-provisioner) 

Контроллер, который позволяет создавать тома в кластере при создании `PVC`

`provisioner` нужно запускать в отдельном ns

```
kubectl create ns nfs-provisioner
```

```
kubectl -n nfs-provisioner apply -f srv-acc.yaml
kubectl -n nfs-provisioner apply -f rbac.yaml
kubectl -n nfs-provisioner apply -f deployment.yaml
```

```
kubectl -n nfs-provisioner logs pod/nfs-client-provisioner-698cfd897-fmbn8
```
### StorageClass

Ключевая роль `StorageClass` — обеспечение **динамического выделения хранилища** (Dynamic Provisioning). Когда `PVC` запрашивает определенный `StorageClass`, система автоматически вызывает соответствующий `provisioner`, **приложение** которое создает `PV` "на лету". Вся "магия" `StorageClass` опирается на такие приложения.

## Ключевые компоненты StorageClass

- `provisioner`: Указывает, какой плагин для работы с томами должен использоваться для создания `PV`. Например, `kubernetes.io/aws-ebs` для Amazon EBS или, как в нашем случае, `kryukov.local/nfs`.
- `parameters`: Параметры, специфичные для конкретного `provisioner`. Например, для `aws-ebs` это может быть тип диска (`gp2`, `io1`), а для NFS — путь к серверу.
- `reclaimPolicy`: Политика возврата (`Delete` или `Retain`), которая будет установлена для `PV`, созданных с помощью этого класса. По умолчанию используется `Delete`, что означает, что при удалении `PVC` будет удален и `PV`, и физический том.
- `allowVolumeExpansion`: Если установлено в `true`, позволяет увеличивать размер тома после его создания.
- `mountOptions`: Опции монтирования, которые будут применены к `PV`.

Создадим `StorageClass` и `PVC`

```
kubectl -f apply storage-class.yaml
```

```
kubectl get storageclasses
```

```
kubectl -n work apply -f pvc.yaml
```

И теперь посмотрим на созданные `PVC` и `PV`

```
kubectl get pv,pvc
```

Заметим, что у нас создался автоматически `PV` с названием `persistentvolume/pvc-0506a70f-5361-4f1a-b727-c5a0987df50f` и ровно такая же директория создалась на самом nfs сервере

```
**ubuntu@nfs-server**:**/srv/nfs/k3s$ ls
work-nfs-pvc-pvc-0506a70f-5361-4f1a-b727-c5a0987df50f
```

Теперь удалим наш `PVC`

```
kubectl -n work delete pvc nfs-pvc
```

```
root@control:/home/ubuntu/manifests/nfs-provisioner# kubectl get pvc,pv -n work
No resources found
```

`PV` удалился автоматически, точно также как и директория на nfs сервере.
